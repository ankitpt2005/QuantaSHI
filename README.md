# QuantaSHI — Heterogeneous AI Infrastructure Framework

QuantaSHI is an event-driven simulation of energy-aware AI-inference scheduling. A single authoritative simulation clock drives synthetic users, the scheduling engine, three virtual servers, lifecycle events, and a matched round-robin baseline.

The headline measurements are **estimated simulation outputs**, not measurements from physical data-centre hardware. Server rates, power curves, and hardware profiles are explicit model inputs that require calibration before any real-world claim.

## Live demo

```bash
python run_simulator.py
```

Open [http://localhost:8000/](http://localhost:8000/). The **Live Control Centre** is the one operational access channel: its Synthetic users, Virtual data centre, and Decision engine views all read the same simulation session. It starts the whole experiment with one action and supports deterministic seed resets, scenario selection, pause/resume, and speed control. The dashboard compares QuantaSHI with uniform round robin on the identical generated trace.

The browser polls `/api/simulation/state`; it never generates traffic, charts, decisions, or energy values itself. Use `POST /api/simulation/control` with `START`, `PAUSE`, `RESUME`, `RESET`, or `SPEED` for external control.

## Simulation scope and platform note

- Synthetic users are generated by code; they are not human users or per-user LLM agents.
- `srv_gpu_01`, `srv_acc_02`, and `srv_cpu_03` model selected capacity, queueing, latency, and power behaviours; they are not digital replicas of H100, Telum, Xeon, or LinuxONE systems.
- The current Windows run validates Python, NumPy, SciPy/HiGHS and the bundled statevector micro-benchmark. Installing and running those exact versions on IBM LinuxONE/s390x remains a separate compatibility check.
- QAOA is a small, classical statevector simulation only. The project makes no quantum-advantage claim.

## Component architecture

QuantaSHI is divided into three cleanly isolated component interfaces, with shared/common utilities kept outside:

```
QuantaSHI/
│
├── user_interface/              # 1. USER INTERFACE (Workload Generator)
│   ├── agent.py                 # [AI AGENT] UserWorkloadAgent: Generative persona-based query synthesis
│   ├── USERS_SPECIFICATION.md   # Workload generator mathematical specification
│   ├── models.py                # User & InferenceRequest schemas
│   ├── distributions.py         # Azure trace calibrated Gamma/Lognormal token samplers
│   ├── prompt_corpus.py         # Real-world prompt template corpus
│   ├── topology.py              # 100-user 2D network mesh topology generator
│   ├── generator.py             # Discrete-event workload generator
│   ├── cli.py                   # Workload generation CLI
│   ├── README.md                # User interface documentation
│   └── web/                     # Dedicated User Interface Visualizer (with AI Agent panel)
│
├── server_interface/            # 2. SERVER INTERFACE (Virtual Data Centre)
│   ├── agent.py                 # [AI AGENT] ServerOpsAgent: Autonomous cluster telemetry & SRE diagnostics
│   ├── SERVERS_SPECIFICATION.md # Heterogeneous cluster architectural specification
│   ├── models.py                # ServerHardwareConfig, ExecutionTask, CompletionEvent
│   ├── power_model.py           # Fan et al. (ISCA 2007) non-linear power curve formula
│   ├── execution_engine.py      # Two-phase prefill/decode latency & SLO calculation
│   ├── cluster.py               # VirtualDataCentre cluster coordinator (H100, L4, Xeon)
│   ├── cli.py                   # Server cluster execution test CLI
│   ├── README.md                # Server interface documentation
│   └── web/                     # Dedicated Server Interface Visualizer (with AI Agent panel)
│
├── system_interface/            # 3. SYSTEM INTERFACE (Decision & Optimization Engine)
│   ├── agent.py                 # [AI AGENT] SystemReasoningAgent: Decision attribution & Pareto reasoning
│   ├── SYSTEM_SPECIFICATION.md  # Optimization problem formulation & routing policies
│   ├── models.py                # RoutingPolicy, OptimizationWeights, DispatchDecision
│   ├── feasibility.py           # Deterministic feasibility filter & joint concurrency latency
│   ├── buffer.py                # Adaptive slack-aware mini-batch buffer
│   ├── qubo_builder.py          # Upper-triangular QUBO matrix with slack variables
│   ├── solvers.py               # Multi-solver suite (HiGHS MILP, SA, QAOA statevector, GESF)
│   ├── optimizer.py             # QuantaSHIOptimizer Pareto multi-objective solver
│   ├── scheduler.py             # QuantaSHIScheduler connecting users to servers
│   ├── README.md                # System interface documentation
│   └── web/                     # Dedicated System Interface Visualizer (with AI Agent panel)
│
├── tests/                       # COMMON: Shared Unit Test Suites
│   ├── test_agents.py           # Comprehensive tests for all 3 autonomous AI agents
│   ├── test_tiny_exhaustive.py  # N=2, K=2 verification (HiGHS vs QUBO exact equivalence)
│   ├── test_user_interface.py   # Tests for user_interface
│   ├── test_server_interface.py # Tests for server_interface
│   ├── test_system_interface.py # Tests for system_interface
│   └── test_simulation_engine.py # Tests for authoritative simulation engine
│
├── ai_agent_client.py           # COMMON: Central OpenRouter LLM Gateway
├── run_simulator.py             # COMMON: Local HTTP Server & AI Agent REST API
├── index.html                   # COMMON: Unified Control Portal (Tab Switcher)
├── simulation_engine.py         # COMMON: Authoritative matched experiment/session
├── dashboard/                   # COMMON: Live Control Centre (backend-derived state)
└── README.md                    # COMMON: Project Overview
```

## Quick Start

### 1. Launch the Unified Simulator Portal
```bash
python run_simulator.py
```
Then navigate to [http://localhost:8000/](http://localhost:8000/) in your browser. The Live Control Centre is the real end-to-end simulation. The old component explorers remain as development references only; do not use them as live telemetry:
- 👤 **User Interface** (`/user_interface/web/`)
- 🖥️ **Server Interface** (`/server_interface/web/`)
- ⚡ **System Interface** (`/system_interface/web/`)

### 2. Run All Unit Tests
```bash
python -m unittest discover -s tests -p "test_*.py"
```
